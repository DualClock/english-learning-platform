# CMS-3: Новости из фида

Волна после админки: новости приходят сами, без ручной работы.

## Что работает

Раз в 2 часа фоновый сервис забирает фид **News in Levels**, парсит, чистит
HTML и раскладывает по уровням. На главной под «Планом на сегодня» появляется
блок «Новости для тебя» — до 5 карточек под уровень и интересы читателя.

Проверено на живом фиде: **10 новостей загрузились автоматически**, один сюжет
на трёх уровнях (A1/A2/B1) с адаптированными текстами.

## Схема

```
NewsItem            Article              ArticleSection
├ ExternalId (uniq) ├ Slug (uniq)        ├ Slug (uniq)
├ Title             ├ Title              ├ Name
├ Summary           ├ BodyMarkdown       └ SortOrder
├ BodyHtml          ├ BodyHtml
├ SourceName        ├ SectionId →        ArticleRevision
├ SourceUrl         ├ Status             ├ ArticleId
├ Level (A1..C1)    ├ AuthorId           ├ Revision
├ Topics            ├ PublishedAt        └ BodyMarkdown
├ PublishedAt       └ DeletedAt
├ FetchedAt
└ IsHidden
```

**Почему новости и статьи — разные таблицы.** У новости `ExternalId` для
дедупликации при каждой синхронизации; у статьи его нет и не будет. Новость
не нужна через полгода — её можно чистить по дате; статью нельзя. Слияние
заставило бы каждую строку носить поля, неприменимые к половине строк.

`ArticleSection` — отдельно от `Category`: Category это наборы СЛОВ с
прогрессом пользователей, ArticleSection — рубрики текстов.

## Поток новостей

```
INewsSource (интерфейс)
  └─ RssNewsSource        — News in Levels, XML через XDocument
        ↓ NewsFeedEntry (DTO, не сущность)
NewsFetchService          — дедуп по ExternalId, санитизация HTML
        ↓
NewsItems (БД)            ← уникальный индекс ловит гонку параллельных запусков
        ↓
GET /api/news/for-me      — фильтр по уровню + приоритет по интересам
        ↓
NewsForYou (главная)
```

## Решения, которые стоит помнить

**Уровень берётся от источника, не вычисляется.** News in Levels пишет его в
заголовке («– level 1»), мы мапим: level 1 → A1, level 2 → A2, level 3 → B1.
Это снимает need платного AI для определения сложности.

**Новость без уровня не попадает в персональную выдачу.** Показать C1
первогодке хуже, чем не показать ничего: текст, который невозможно прочитать,
отбивает желание заходить.

**Интересы меняют приоритет, но не отсекают.** Человек с редким интересом
получит общую ленту, а не пустой экран при живом блоке.

**Потолок 5 карточек — на сервере.** Ограничение в вёрстке не защита: другой
клиент попросит сотню и превратит главную в ленту.

**Интересы не передаются в адресе.** Сервер берёт их из профиля по токену.
Иначе любой мог бы запросить подборку по чужим темам.

**Уборка по `PublishedAt`, не по `FetchedAt`.** Фетчер может догнать старую
новость — она должна уйти по фактическому возрасту, а не по дате загрузки.

## Дефекты, найденные при приёмке

1. **`RssNewsSource` не был зарегистрирован в DI.** Фоновый сервис получил бы
   пустой список источников и молча работал вхолостую: новостей нет, ошибок в
   журнале тоже. Исправлено.
2. **Фронт звал `/api/next/news`, а контракт — `/api/news/for-me`.** Блок не
   появлялся. Приведено к реальному API.
3. **Анонс начинался с даты** («26-10-2026 07:00 An Australian…»): в карточке
   дата уже есть отдельно, а мусор съедал обе строки clamp'а. Добавлено
   вырезание ведущей метки времени + два теста (включая обратный случай
   «100 people…», чтобы регулярка не съела содержание).
4. **`UserInterests` не чистились при удалении аккаунта.** Поймал
   `AccountDeletionTests` — тест держит реестр `AccountController.UserOwnedRows`
   и падает, если таблица с `UserId` не покрыта. По `/privacy` удаление
   обещано, значит интересы обязаны уходить.

## Что осталось

1. **Статьи (CMS-4)** — схема готова, эндпоинтов и UI нет.
2. **Онбординг интересов** — шаг добавлен агентом, но требует проверки на живом проходе.
3. **BBC и Guardian** — нет уровня, нужен AI. Флаг `News:EnableAiLeveling` не сделан.
4. **Уборка старых новостей** — `NewsCleanupService` написан, но фоновый цикл
   его вызывает только вместе с фетчем; отдельного расписания нет.
