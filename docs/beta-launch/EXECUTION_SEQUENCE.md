### A2. Секреты (40 минут)
`appsettings.Development.json` не исключён в `.dockerignore` (проверено содержимое файла), а
`Dockerfile:8` копирует `EnglishLearningPlatform.API/ ./` целиком: при локальной сборке образа
dev-креды попадают в слои. Сделать: добавить в `.dockerignore` `appsettings.Development.json`
и `.env*`, убрать `appsettings.Development.json` из `bin/` перед сборкой, **ротировать**
JWT-ключ, Gemini-ключ, креды прокси и `NEXTAUTH_SECRET`, добавить gitleaks в CI.
Признак готовности: свежий образ не содержит dev-файла (проверка `docker run --rm <image> ls /app`),
продовый `Jwt__Key` ≠ локальный.

### A3. Critical-CVE: быстрое закрытие без мажор-апгрейда (1–2 часа)
`next@14.2.35` — critical, включая RCE в Image Optimization; `next-auth@4.24.11` — critical.
Апгрейд 14 → 15/16 тянет React 19 и неохватываемый тестами фронт — это отдельный спринт после
беты, не сегодня. Поэтому на бету:
- `images: { unoptimized: true }` в `next.config.mjs` **и** блокировка `/_next/image` на
  reverse-proxy (двойная страховка: конфиг мог не попасть в собранную версию);
- `next-auth` — минорный апгрейд до прощённого 4.24.x (обычно ломающих изменений нет, но
  проверить логин, avatar-route, word-image-route руками);
- прогнать `npm audit --omit=dev --audit-level=high` и записать остаток как принятый риск
  с датой пересмотра.
Признак готовности: `curl -I https://<URL>/_next/image?url=...` возвращает 403/404.

### A4. Заголовки и TLS (1 час)
На фронте сейчас нет ни `headers()`, ни middleware — значит нет CSP, `X-Frame-Options`,
`nosniff`, HSTS. На API отдаётся пять заголовков без HSTS/CSP, а `UseHttpsRedirection`
закомментирован (`Program.cs:287`).
Сделать: `headers()` в Next с `Content-Security-Policy: frame-ancestors 'none'` (остальной CSP
вводить постепенно, иначе сломаешь шрифты и inline-скрипт темы из `layout.tsx:5`),
`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, HSTS; на API —
HSTS и включение HTTPS-редиректа после проверки, что прокси отдаёт правильный scheme.

### A5. Rate limiting за прокси (1–2 часа)
`ForwardedHeaders` отсутствует: все клиенты за Timeweb получают один `RemoteIpAddress`, и
lockout на 5 попыток (`Program.cs:88-90`) превращается в инструмент, которым один скрипт
запирает вход всем остальным. Сделать: включить ForwardedHeaders с доверием **только** сетям
твоего прокси (не `AnyIP`), партицировать лимиты по IP **и** по логину/email, проверить
вручную: 20 неверных входов с одного клиента — остальные всё ещё могут войти.

### A6. Регистрация и AI-квота (2–3 часа) — это деньги, а не паранойя
Регистрация открыта, `EmailConfirmed` при входе не проверяется (`AuthController.cs:114-165`),
квота — 300 AI-запросов на аккаунт в сутки (`AiQuotaService.cs:36`). Десять disposable-аккаунтов
= 3 000 запросов в Gemini за день.
Сделать: доступ к AI-endpoint'ам только после подтверждения email; глобальный дневной бюджет
запросов с алертом (ntfy уже настроен в `appsettings.json:55`); honeypot + лимит регистраций
с одного IP; инвайт-код как опциональный путь (он же станет реферальной механикой набора).

### A7. Что осознанно переносим на после беты
Отзыв JWT и refresh-ротация (пока access живёт 7 дней — снижаем риск CSP и коротким
email-подтверждением, но не трогаем контракт фронта, иначе сломаем вход на старте когорты;
если сокращаешь `Jwt:ExpiryMinutes`, сначала убедись, что фронт реально обновляет сессию,
иначе получишь бесконечные перелогинки у живых тестеров). Серверная проверка результатов
практики (`PracticeController.cs:101-115`), `SixLabors.ImageSharp` 4.x, чистка `UserVersions`,
`MaxLength` на слова в `LearnWords`, Next 15. Каждый перенос — с датой пересмотра.

### A9. Деплой-квитанция: порядок, в котором это выкатывается (добавлено 23.10, после волны 2)

Порядок не рекомендация: новый API без применённых миграций **ломает регистрацию**, потому что
`INSERT` в `AspNetUsers` ссылается на колонки `AcquisitionSource`/`AcquisitionCode`, которых в
боевой базе ещё нет. Молчание в воронке — второй побочный эффект: вставки аналитики намеренно
не трогают UX, поэтому без таблицы гостевых событий `/test` отвечает 200, а funnel читается
нулями.

```
1) dotnet ef database update (или приложенные SQL) — миграции в порядке создания:
   20261023164150_AddAcquisitionAttribution        (две колонки varchar(64), nullable)
   20261023165136_AddFirstChapterActivationIndex   (частичный уникальный индекс)
   20261023190630_AddGuestAnalyticsEvents          (новая таблица + два индекса)
2) Переменные окружения, ни одна не имеет права остаться молчаливым дефолтом:
   Proxy__TrustedCidrs        сети твоего TLS-терминатора (иначе R-02 и R-03 вернутся)
   Analytics__GuestIpSalt     постоянная соль для хеша гостевого IP (без неё счётчик
                              «уникальных гостей» разъезжается по рестартам)
   NEXT_PUBLIC_SITE_URL       боевой домен фронта (иначе OG и canonical = localhost)
   Ai__GlobalDailyRequestLimit, Registration__DailyGlobalLimit  явные числа
3) Сборка образа из зафиксированного SHA release/beta, publish-артефакт проверить на
   отсутствие appsettings.Development.json и uploads/
4) Смоук по §A8 + отдельно: регистрация с ?ref=кодом долетает до выгрузки, /test
   пишет guestStarts/guestCompletions, /privacy открывается, удаление аккаунта на
   тестовом пользователе не оставило сирот в базе
5) Публикация первой ссылки — только после пунктов 1–4
```

Владельцу до публикации вписать в `/privacy` и `/terms` реквизиты вместо `[РЕКВИЗИТЫ]`
и подтвердить адрес `hello@lexicon.app`.

**Как это прошло на самом деле (24.10, 02:20–02:35, `https://5.129.192.216.sslip.io/`).**
Пункт 1 — не `dotnet ef database update` на сервере (tam не стоит .NET и design-time падает
на валидации `Jwt:Key`), а `dotnet ef migrations script 20261023111521_AddWordVisuals` локально
и `psql -v ON_ERROR_STOP=1` на сервере: история 24 → 27, перед этим `pg_dump -Fc`. Пункт 2 —
все четыре переменные заданы, но не в юните, а в новых дропинах
`lexicon-api.service.d/{proxy,prod-runtime}.conf` с правами 0600. Пункт 3 — вместо образа
`dotnet publish -r linux-x64 --self-contained` и tar-перенос: сервер смотрит на
`/opt/lexicon/api/EnglishLearningPlatform.API` как на apphost, дотнета в системе нет. Два
самострела, которые стоит помнить: tar с Windows не перенёс бит исполнения, и сервис
крутился в `activating` с `203/EXEC`, пока не сделал `chmod +x`; а скрипт переноса секретов
заодно скопировал из дев-файла строку коннекта с `Port=5433` и перебил значение юнита —
каталог ответил `503`, строчку из дропина удалил, каталог снова `200`. Пуша в GitHub не
было, поэтому «сборка из зафиксированного SHA» сейчас нечем доказывается.

Из пункта 4 проверено живыми запросами: миграции под новым API, все восемь публичных
маршрутов, `/t/stasya → ?ref=stasya`, анонимный каталог (18 книг), запись гостевых событий
и `20×200 + 5×429` на лимите, honeypot (`400`, строки в `AspNetUsers` нет), гейт почты
(`403 email_confirmation_required`), `X-Seed-Key` на воронке. **Не проверено:** регистрация
по ссылке с `?ref=` долетает до выгрузки (нужен реальный клик с телефона), сквозное удаление
аккаунта на боевой базе, OG-карточка в валидаторе Telegram/VK. Бонусом найден и закрыт
дырявый контур доступа к аналитике: `Seeder:Key` на сервере не был задан вообще, а среда
стояла `Development`, поэтому `AdminKeyGuard` пропускал любого вошедшего — обычный
тестовый аккаунт читал воронку проекта со всеми кодами каналов. Подробности и команды
восстановления — `security/verification-log.md`, раздел «Выкатка».
