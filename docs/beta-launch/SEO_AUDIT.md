# SEO: аудит состояния и план на 90 дней

Дата проверки: 23.10.2026. Техническая часть — read-only разбор `frontend/src/app` и собранного
`.next`, подтверждён лично по ключевым пунктам. Рыночная часть — веб-источники, ссылки в конце.

## Главная правда

Главный поиск в России — Яндекс (71–73% по состоянию на сентябрь 2026, [inclient](https://inclient.ru/search-engine-russia-stats/), [botfaqtor](https://botfaqtor.ru/blog/reyting-poiskovykh-sistem-v-rossii/)).
Новый домен без ссылок: индексация 2–4 недели, показы 3–6 недель, первые клики 6–10 недель.
Ahrefs по 1M+ URL (май 2025): в топ-10 за год попадает 1,74% новых страниц. Отсюда — SEO не
канал набора беты за 14 дней. Оно нужно, чтобы к третьему месяцу у продукта появился
бесплатный входящий трафик, и чтобы страницы книг работали как лид-магниты.

## Что сейчас мешает индексации (проверено в коде)

1. **Публичные разделы отдают 200 со спиннером.** `src/middleware.ts` отсутствует (проверено
   `ls`), страницы клиентские: `frontend/src/app/books/page.tsx:1` — `'use client'`, гейт живёт в
   `frontend/src/components/AppLayout.tsx:165-199`. Поисковик без JS видит «Проверяем сессию»,
   с JS — переезд на `/login`. Это означает: весь контент для робота непубличный.
2. **Нет ни одной индексируемой страницы книг.** `frontend/src/app/books/[slug]/page.tsx` —
   файла нет; весь лендинг ведёт четыре книги на `/books` (`src/app/page.tsx:110,122`).
   Публичного содержательного контента фактически одна страница — главная.
3. **`sitemap.ts` и `robots.ts` отсутствуют** → `/sitemap.xml` и `/robots.txt` отдают 404.
4. **Метаданные только в корне** (`src/app/layout.tsx:34-67`): нет `title.template`, нет
   per-page metadata, нет canonical. У `/login`, `/onboarding`, `/reset-password` тот же
   title/description, что у главной (подтверждено в собранном `.next/server/app/*.html`).
5. **Служебные страницы индексируются**, включая `confirm-email` и `reset-password` с токеном
   в query. `noindex` стоит только на `admin/feedback` и `offline`.
6. **`metadataBase` привязан к `NEXTAUTH_URL`** (`src/app/layout.tsx:30,35`); в собранном HTML
   `og:image` = `http://localhost:3000/og.png`. В Telegram/VK превью не соберётся — это ломает
   кликабельность каждого поста из outreach-ките.
7. **JSON-LD нет вообще** (поиск `ld+json` по `src` — 0 совпадений).
8. **Контент ниже сгиба скрыт до JS**: `components/landing/Reveal.tsx:14-25` + `motion.ts:50-67`
   стартуют с `opacity: 0`, в `src/app/page.tsx:103-168` на этом держатся H2 «Возможности»,
   «Библиотека», финальный CTA. Плюс `globals.css:312-336` — H1 появляется 900 мс, абзац с
   задержкой 700 мс. Риск по LCP и по «текст невидим без JS».
9. Мелочи, которые всё равно повлияют: нет `not-found.tsx`, `next/image` не используется
   (`BookCover.tsx:31-37`), 3 семейства шрифтов и 20 `@font-face` без preload, нет страниц
   `privacy`/`about`/`contacts` (для Яндекса это минус к доверию молодого домена), пагинация
   кнопками без `<a href>`.

## Пять фиксов до старта беты (по 1–1,5 часа каждый)

1. `src/app/sitemap.ts` + `src/app/robots.ts`: sitemap публичных URL, disallow `/api/`, `/admin/`.
2. Отдельная `NEXT_PUBLIC_SITE_URL`, применить в `metadataBase` и OG; проверить собранный HTML
   на проде, а не локально.
3. `title.template` + per-page metadata; `robots: noindex` всем auth/служебным страницам.
4. `src/middleware.ts`: 307 на `/login` для приватных маршрутов + `X-Robots-Tag: noindex`.
   Приватное должно уходить 307/404, а не 200 со спиннером; `Disallow` сам по себе URL из
   индекса не убирает.
5. Публичная SSR-страница книги `/books/[slug]` (автор, уровень, описание, первая глава или
   абзац, CTA) + `Book` JSON-LD (`inLanguage`, `author`, `isAccessibleForFree`) и ссылки с
   главной. Без этого пункта всё остальное — косметика.

## Очередь контента: programmatic SEO вокруг public-domain книг

Ставка на то, чего нет ни у кого в RU-сегменте: public-domain текст + русский интерфейс +
пословный словарь + SRS + уровень. Никто из конкурентов не соединяет это в индексируемые
страницы: Puzzle English прячет книги за подпиской, Skyeng даёт подборки вместо читалки,
LingQ слаб в RU-SEO, Readlang не имеет RU-страниц, Beelinguapp не делает глубоких страниц по
книгам, anylang/liteka/madbook/2books — малые домены со слабым UX.

Приоритет шаблонов (каждая страница обязана нести уникальные данные, иначе Google с 2024
наказывает scaled content abuse, Яндекс — за малополезные страницы,
[спам-политики Google](https://developers.google.com/search/docs/essentials/spam-policies)):

| Маршрут | Закрываемый запрос | Что делает страницу полезной |
|---|---|---|
| `/books/[slug]` | «Alice in Wonderland на английском с переводом» | доля знакомых слов для твоего уровня, sample, кому подойдёт |
| `/books/[slug]/vocabulary` | «слова из книги Алиса в стране чудес» | топ-100 слов в контексте цитат, готовая колода |
| `/books/level/a2` | «адаптированные книги на английском A2» | методика, покрытие словаря, время на книгу |
| `/test` | «определить уровень английского» | результат за 3 минуты без регистрации (онбординг уже содержит placement-тест) |
| `/compare/[competitor]` | «Puzzle English или LingQ», «аналоги LingQ» | честная таблица и сценарии, не affiliate-мусор |
| `/grammar/[topic]` | «present simple для начинающих» | правило + примеры из корпуса наших книг |

Кластеры запросов, под которые стоит писать (полные частотности без Wordstat не подтверждаю —
это оценка по характеру выдачи): «читать книги на английском с переводом слов»,
«книги с параллельным переводом», «адаптированные книги на английском», «английский по книгам»,
«как начать читать на английском», «сколько слов нужно знать для чтения», «книги на английском
A2/B1», «английские слова по темам с переводом и транскрипцией», «карточки для слов»,
«перевод слов по клику», «приложение для чтения английских книг», «что почитать после
адаптированных книг», «слова из [название книги]», «аудиокнига на английском с текстом».

Юридическая рамка: public-domain тексты в РФ — можно; чужие переводы и адаптации — нельзя;
современные книги вроде «Гарри Поттера» — только обзорный материал, без текста.

## Roadmap

**Дни 1–14.** Пять фиксов выше; подключённые Google Search Console, Bing, Яндекс.Вебмастер,
Метрика; 15 книг × 3 главы, 5 уровневых хабов, 3 страницы грамматики, `/test`; юридическая
проверка PD-статуса каждой книги. Бету в эти дни набираем руками — см. `BETA_LAUNCH_PLAN.md`.

**Дни 15–30.** 40–60 книг с глоссами, 100–150 публичных глав, 8–10 статей под информационные
кластеры, 5–10 первых упоминаний в чужих материалах (форумы, обзоры, посты на Habr).

**Дни 31–60.** 100–150 книг, страницы словарей по каждой, 10–15 сравнительных, чистка страниц
без показов по данным вебмастеров.

**Дни 61–90.** 200–300 книг, но только там, где есть реальные глоссы; 30–40 ссылок; цикл
обновления по фактическим показам.

**Что позже:** hreflang при появлении EN-версии, IndexNow, видеосхема, расширенные FAQ (учти,
что rich-сниппеты FAQPage Google с 2023 показывает только авторитетным гос/медийным сайтам —
не рассчитывай на них).

Реалистичное ожидание к 90-му дню при 100+ качественных страницах: 50–300 органических визитов
в месяц (оценка, не гарантия). 1000+/мес — горизонт 6–12 месяцев.

## Что нужно проверить на живом URL

Всё выше перечисленное подтверждено по коду и собранному HTML, но не по продащейся конфигурации:
нет данных, какой домен отдаётся, какие заголовки ставит Timeweb/Reverse-proxy, редирект ли
www → apex, HTTPS ли everywhere, отвечает ли `/health` из публичной сети. Как только пришлёшь
URL — прогоню повторный аудит уже по факту и поправлю приоритеты.
