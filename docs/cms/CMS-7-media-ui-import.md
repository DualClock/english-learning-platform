# CMS-7: Медиа через абстракцию + UI импорта

Завершение двух линий: картинки слов больше не знают, где лежит файл, а
импорт слов доступен из админки, а не только через curl.

## Картинки слов за `IMediaStorage`

Вся обработка ImageSharp сохранена (проверка сигнатуры, минимум 16×16,
ресайз до 512 px, WebP q82) — на абстракцию перешла только **запись и
удаление**.

**Кодирование в память, а не сразу на диск.** Хранилище принимает поток, и
это заодно убирает недописанный файл, если ImageSharp упадёт на середине.
Картинка до 512 px — десятки килобайт, память не проблема.

**Старая строковая проверка пути удалена.** Раньше было «начинается с
`/uploads/word-images/`, в имени нет `/`, `\`, `..`». Такая проверка обходится
юникод-нормализацией и символическими ссылками. Теперь путь нормализуется
через `GetFullPath` и сравнивается с корнем **с завершающим разделителем** —
без него корень `/media` пропустил бы соседний `/media-backup`.

### Проверено вживую

```
загрузка PNG 64×64    → /uploads/word-images/<guid>.webp, файл на диске, RIFF/webp
замена картинки       → старый файл удалён, новый на месте
удаление картинки     → файл исчез с диска
в браузере            → naturalWidth = 512, отдаётся через /api/word-images/
```

### Про 404 на `/uploads/...`

Прямой адрес из базы отдаёт **404** — и это правильно. Фронт сознательно
переводит его на `/api/word-images/{name}` (`WordIllustration.uploadedImageSrc`).
В базе лежит хост-независимый путь, браузер ходит через API-маршрут. Это
документировано в коде, не дефект.

## UI импорта

Кнопка «Импорт слов» в шапке выбранной категории. Для удалённых категорий
скрыта — заливка слов в удалённую создала бы невидимое.

- подсказка формата CSV и JSON **до** выбора файла
- «Проверить» (dryRun) и «Импортировать»
- отчёт: «Добавлено N, пропущено M» с русской плюрализацией
- ошибки и предупреждения **с номерами строк** — админ ищет их в файле глазами
- после реального импорта файл сбрасывается (повторная отправка дала бы дубли)
- 401/403 посреди работы переключает на «Нужны права администратора», а не
  «файл не подошёл»

### Проверено вживую через форму

Файл с BOM, дублем и битой строкой:

```
dryRun:        «Добавлено 1 слово, пропущено 0. Ошибки в 1 строке... 1 предупреждение»
               стр. 3 — Нужны английское слово и перевод
               стр. 4 — «ui-test-word» уже был в строке 2
реальный:      файл сброшен, категория 21 → 22 слова
в базе:        только одна строка ui-test-word (дубль не создан)
```

## Дефект, найденный агентом

**На 409 сервер кладёт текст исключения БД в `detail`** — и админ увидел бы
SQL-ошибку вместо объяснения. Разбор ошибок переставлен на приоритет
`message → title → error → detail`.

## Два прогона `next build` сломали dev-сервер

Оба раза после `next build` все `/_next/static/*` отдавали 404, страница
монтировалась без JS и вставала на спиннере «Загружаем категории». Форма входа
в этом состоянии уходила **GET-запросом с паролем в адресной строке**.

**Правило:** после `next build` dev-сервер нужно поднимать заново (`rm -rf .next`
+ `npm run dev`). Агентам `next build` запускать запрещено — только `tsc` и
`lint`.
