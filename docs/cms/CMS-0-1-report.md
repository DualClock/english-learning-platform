# CMS-0 … CMS-2: что сделано

Волны 1–3 плана внедрения CMS. Код, миграции и тесты — в репозитории;
здесь зафиксированы решения и их причины, чтобы следующая волна не
переоткрывала тот же вопрос с нуля.

## CMS-0 — RBAC

### Роли

`Security/AppRoles.cs` — единственное место, где живут имена ролей.
`Admin` и `User`. Роль `User` константой, но никому не назначается: она
описывает отсутствие привилегий, а не отдельную выдачу.

`Services/RoleSeeder.cs` создаёт роли при старте и выдаёт `Admin` адресу из
`Admin:BootstrapEmail`. Через конфиг, а не «первому зарегистрированному»:
на чистой базе первым регистрируется тот, кто первым открыл стенд.

На стенде — `Admin__BootstrapEmail=nik@mail.com`. На проде переменной
по умолчанию нет, и это правильно: пока адрес не задан, админки нет ни у кого.

### JWT

`AuthController` читает роли из `AspNetUserRoles` при логине и при refresh.
Роль едет под `ClaimTypes.Role` (`AppClaims.Role`). `Program.cs` задаёт
`RoleClaimType = AppClaims.Role`.

Без этой пары `[Authorize(Roles = "Admin")]` отвечает 403 **всем**, включая
админа: роль выписана под одним ключом, ищется под другим. Два теста держат
пару согласованной — `Program_ConfiguresJwtRoleClaimType` и
`AdminToken_CarriesRoleClaimUnderAppClaimsRole`.

Регистрация токен выдаёт с пустым списком ролей явно, чтобы «прочитаем из
базы на всякий случай» никогда не превратилось в путь выдачи админки.

### Админ-эндпоинты

`X-Seed-Key` убран с `/api/admin/seed-*`. Теперь `[Authorize(Roles = AppRoles.Admin)]`.
Старый механизм был статическим секретом в заголовке: он жил в деплой-скриптах,
не имел срока жизни и в `Development`-режиме без настроенного ключа открывал
служебные эндпоинты любому.

`EveryAdminRoute_RequiresAdminRole` — структурный тест: собирает экшены под
`/api/admin/*` из сборки и требует роль. Точечный тест на один URL не заметил
бы следующий эндпоинт без атрибута — а это ровно тот класс ошибки, что
описывает история `AiEndpointGateTests`.

### Фронт

- Роль приходит в ответ `POST /api/auth/login` (`roles: []`) и живёт в
  NextAuth-токене.
- `src/middleware.ts`: `/admin` требует роль. Без роли — **404**, не 403:
  403 подтверждает существование раздела.
- Без `NEXTAUTH_SECRET` middleware не может расшифровать куку и закрывает
  админку. Честный отказ лучше ложного пропуска.

## CMS-1 — Soft Delete

### Схема

`DeletedAt` + `DeletedByUserId` (`Models/ISoftDeletable.cs`) на `Word`,
`Category`, `CategoryWord`, `Book`. Время отвечает «когда», автор — «кто»;
восстановление — обнуление обоих.

### Глобальный фильтр

`HasQueryFilter(e => e.DeletedAt == null)` на `Word`, `Category`, `Book`.

**На `CategoryWord` фильтра нет — сознательно.** У `UserCategoryWordProgress`
обязательный FK на `CategoryWord`; фильтр на родителе сделал бы навигацию от
прогресса к слову возвращающей `null` при живой строке в базе (EF предупреждает
об этом при сборке миграции). Удалённое слово отсекается явно в выдаче
категории — `Include(c => c.Words.Where(w => w.DeletedAt == null))`. Тест
`CategoryWord_HasNoQueryFilter_OnPurpose` объясняет цену изменения.

### Каскад, который стирал чужой прогресс

Было:
```
UserCategoryWordProgress → CategoryWord   Cascade
CategoryWord            → Category        Cascade
```
Одно удаление слова из категории уносило «выучено» у всех пользователей по
этому слову. Строка прогресса не хранит ни даты, ни истории — восстановить
нельзя.

Стало `Restrict` на обеих связях. Подтверждено в живой базе:
`confdeltype = 'r'` для обоих ограничений.

### Частичные уникальные индексы

Уникальность слага категории и пары `(CategoryId, English)` теперь действует
только на живые строки (`WHERE "DeletedAt" IS NULL`,
миграция `ActiveOnlyUniqueIndexes`).

Пока индекс был полным, админ, удаливший категорию, не мог создать её заново
никогда: INSERT падал на индексе, клиент получал `500 an error occurred while
saving` без намёка на причину. Контроллер при повторном создании восстанавливает
прежнюю строку вместо второй.

### Побочный дефект, найденный при ревью

`SrsService.GetTodayQueueAsync` не фильтровал удалённые слова, а
`GetReviewCountAsync` — фильтровал. Счётчик и очередь расходились:
«Повторить» обещало карточку, которой нет в счётчике. Добавлено
`uw.Word.DeletedAt == null` в очередь, в квиз (`ReviewController`) и в
оба пути диктанта (`PracticeController`).

## CMS-2 — админский API и UI

### Эндпоинты

`Controllers/AdminContentController.cs`, префикс `/api/admin/content`,
вся группа под `[Authorize(Roles = Admin)]`:

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/categories?includeDeleted=` | список со словами |
| POST | `/categories` | создать (или восстановить удалённую с тем же слагом) |
| PUT | `/categories/{id}` | изменить |
| DELETE | `/categories/{id}` | мягко удалить |
| POST | `/categories/{id}/restore` | восстановить |
| POST | `/categories/{id}/words` | добавить слово |
| PUT | `/words/{id}` | изменить слово |
| DELETE | `/words/{id}` | мягко удалить |
| POST | `/words/{id}/restore` | восстановить |
| GET | `/books?includeDeleted=` | список книг |
| POST | `/books/{id}/publish` | снять владельца → книга в гостевом каталоге |
| DELETE | `/books/{id}` | мягко удалить |
| POST | `/books/{id}/restore` | восстановить |

### Кэш: почему правка видна сразу

Витрин три: публичный каталог (6 ч), гостевой каталог (6 ч), превью глав (12 ч).
Пока админских правок не было, такой TTL был нормален; с CMS он означал
«сохранил — пользователь видит старое до шести часов».

`Services/ContentCacheInvalidator.cs` — единая точка сброса. Вызывается из
каждого мутирующего экшена и из сидов. Отдельный сервис, а не
`_cache.Remove(...)` в контроллерах: вызывающий не должен знать, кто и где
кэширует, иначе четвёртую витрину забудут добавить ровно в одном месте.

Инвалидатор не трогает чужие ключи (`unrelated-key` остаётся): в том же
`IMemoryCache` живут квоты AI и счётчики регистрации, их сброс обнулил бы
защиту от брутфорса.

### UI

- `/admin` — общий layout с навигацией.
- `/admin/content/categories` — категории слева, слова справа: создание,
  правка перевода, мягкое удаление, восстановление, «Показать удалённые».
- `/admin/content` — книги: публикация, удаление, восстановление.

Клиент (`admin/content/api.ts`) ходит через `/api/next/[...path]`: серверный
прокси подставляет access-токен из httpOnly-куки. Браузер токена не видит.

### Дефекты, найденные при живом прогоне UI

1. **429 посреди работы.** Партиция лимита строилась по заголовку
   `X-Seed-Key`, которого с CMS-0 в запросе нет, — все админы мира падали в
   одну IP-корзину на 10 запросов / 5 минут. Теперь партиция по id
   пользователя, лимит 240/мин. Попутно выяснилось, что `UseRateLimiter`
   стоял **до** `UseAuthentication`, то есть `context.User` был пуст всегда;
   порядок исправлен.
2. **Слаг из кириллицы.** «Проверка UI» → `проверка-ui`: ссылка приходила
   процентно-закодированной. Добавлена транслитерация, теперь `proverka-ui`.
3. **Порт фронта.** Если на 3000 сидел старый Next, новый молча уезжал на
   3001, а проверка смотрела на 3000. Скрипт запуска теперь освобождает оба
   порта.

## Тесты

| Файл | Что держит |
|---|---|
| `Security/AdminRbacTests.cs` | политика роли Admin, claim в реальном JWT, все `/api/admin/*` под ролью |
| `Security/AdminPartitionIsolationTests.cs` | партиция лимита по пользователю, анонимный флуд не отрезает админа |
| `Migrations/SoftDeleteTests.cs` | фильтры, сохранность прогресса, `Restrict` вместо `Cascade` |
| `Migrations/SoftDeleteSqlTests.cs` | трансляция фильтров в SQL на Npgsql (InMemory их не показывает) |
| `Tests/Services/AdminContentTests.cs` | сквозной путь правок на уровне контроллера |
| `Tests/Services/AdminSoftDeleteReuseTests.cs` | частичные индексы, повторное создание после удаления |
| `Tests/Services/AdminCategorySlugTests.cs` | транслитерация слага |
| `Tests/Services/ContentCacheInvalidatorTests.cs` | сброс кэшей, чужие ключи не трогаются |
| `frontend/src/lib/admin-access.test.mjs` | роль в middleware, имена куки |

`SoftDeleteTests` проверяют данные на InMemory, `SoftDeleteSqlTests` — SQL на
настоящем провайдере. Разделение вынужденное: **InMemory игнорирует `Where`
внутри `Include`**, и тест фильтра навигации на нём был бы зелёным вхолостую.

Сквозной сценарий на живом API — `scripts/cms-e2e-live.py`, 21 проверка.

## Миграции

1. `20261027140049_AddSoftDeleteContent` — поля `DeletedAt`/`DeletedByUserId`,
   индексы, `Cascade` → `Restrict` на двух связях.
2. `20261027151243_ActiveOnlyUniqueIndexes` — частичные уникальные индексы
   слага категории и пары (CategoryId, English).

## Что осталось недоделанным

1. **Отзыв роли.** Роль живёт в access-токене до 7 дней. Снятие админки
   отзывается только при refresh; нужен `SecurityStampValidator` или короткий
   срок жизни админского токена.
2. **Уборка медиа.** EPUB и `BookKeyWords` мягко удалённой книги остаются на
   диске — нужна отдельная задача.
3. **Импорт CSV/JSON и AI-ассистент** (CMS-5) не начаты.
4. **Media-абстракция** `IMediaStorage` (CMS-3) не начата: загрузка файлов
   по-прежнему идёт в локальную `uploads/`.
