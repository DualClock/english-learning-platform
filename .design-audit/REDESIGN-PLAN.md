# ЧАСТЬ 1. Дефекты, не относящиеся к вкусу

Каждый — с механизмом и адресом.

## Д-1. Имя пользователя = технический email-локаль
**Симптом:** «Доброй ночи, audit-1793045167713»; то же в сайдбаре, профиле, настройках.
**Механизм:** `dashboard/page.tsx:109-113` — фолбэк
`session?.user?.name || profile?.displayName || email.split('@')[0]`.
Имя в онбординге необязательное, `displayName` приходит `null`
(`api/auth/[...nextauth]/route.ts:89`), сайдбар отдельно показывает `session?.user?.email`.
**Затрагивает:** 4 экрана. **Стоимость:** ~1 час + тест.

## Д-2. Кнопка «Добавить книгу» молчит
**Симптом:** после клика счётчик остаётся «0 книг», тоста нет, список не меняется.
**Механизм:** API отвечает 200 (проверено вызовом). `addPopularBook`
(`books/page.tsx:165-174`) вызывает `reloadBooks()` → `invalidateCache('/api/books')`
+ `refreshBooks()`. Предположение: данные не перерисовываются либо тост рендерится
мимо вьюпорта. **Требует диагностики до правки** — `setTimeout` не решение.

## Д-3. ~~Онбординг не завершается~~ — ЛОЖНАЯ ТРЕВОГА, снято
**Что было записано в аудите:** на шаге 2 «Начать» не уводит с `/onboarding`.
**Что выяснилось при разборе 2026-10-26:** сценарий аудита сам был неполным.
`register()` отправляется, `/api/next/auth/register` отвечает 200,
`/api/auth/callback/credentials` — 200, появляется шаг «Добро пожаловать!»
с кнопкой «Выбрать первую книгу», сессия живая, `/dashboard` открывается.
Проблема была в тесте: второй клик уходил до отрисовки шага 2.
**Вывод:** дефекта нет. Пункт из волны 2 убран.

## Д-6. Гонка шагов онбординга (найдено при разборе Д-3)
Кнопка `onboarding-submit` переключает шаг на «цель», но регистрация
происходит только по `onboarding-goal-continue`. Если автоматизация (или
нетерпеливый пользователь с двойным кликом) нажимает раньше отрисовки,
клик теряется без обратной связи. Не блокер, но стоит `disabled` на время
перехода шага. Отложено до волны 2.

## Д-4. Читалка: управление невидимо
**Механизм:** `ReaderShell.tsx:123-127` — `showChrome()` ставит скрытие через **3200 мс**.
На мобиле ховера нет, вернуть панель нечем. Прогресса по книге на экране нет.
**Важно:** пагинация считает **колонки**, не высоту (`lib/reader/pagination.ts` —
`pageIndexFromLeft`, `pageCountFromLastLeft`), поэтому нижняя панель не ломает математику.

## Д-5. Две грамматики карточек в одном экране
`/books`: `StoryCard` — горизонтальная, миниатюра `w-14`, сетка `xl:grid-cols-5`;
`ClassicCard` — вертикальная, обложка `w-full`, сетка `md:grid-cols-2`.
Секции по уровням дают 1/3/5/1 книгу → дыры в сетке.

# ЧАСТЬ 6. Как выглядит «готово»

Для каждой волны — три обязательных артефакта:
1. **Диффы** с осмысленными сообщениями, без `@ts-ignore`/`eslint-disable`.
2. **Тесты:** unit для логики (`display-name`, пагинация), E2E для поведения
   (добавление книги, онбординг), скриншоты для вида.
3. **Отчёт** «сделано / не сделано / блокер» с реальными логами прогона.
