# Reader 3.0 — состояние и проверка

Документ фиксирует, что из плана Reader 3.0 сделано, чем это проверено и
какое решение принято по самому рискованному модулю — постраничной вёрстке.

## Этап 0. Спайк вёрстки: GO

Скрытый маршрут `/reader-lab` (реальный текст, Literata, абзацы, картинка,
стихи, смена кегля и полей) прогнан Playwright в трёх конфигурациях:

| Проект | Движок | Результат |
|---|---|---|
| `chromium` | Desktop Chrome 1280×720 | 21 страница, 0 пустых |
| `webkit` | Desktop Safari 1280×720 | 21 страница, 0 пустых |
| `iphone` | WebKit, 390×844, touch | 21 страница, свайп листает |

Проверялось не «страница открылась», а контракт движка:

- число колонок совпадает с числом страниц (`scrollWidth ≈ pages × width`);
- на каждой странице есть видимые строки — пустых колонок нет;
- после «A+ A+» читатель остаётся в том же предложении;
- после reload то же предложение видно на экране;
- свайп пальцем перелистывает страницу.

Команда:

```bash
cd frontend
npm run test:e2e:lab
```

### Что пришлось починить в движке по итогам спайка

1. **Пустая страница на холодной загрузке.** `document.fonts.ready` в dev
   может не разрешиться, а контейнер в первом кадре ещё без размера. Теперь
   ожидание шрифтов ограничено 1,2 с, размер контейнера перепроверяется до
   30 кадров, а после загрузки страницы и после прихода шрифтов делается
   повторный замер.
2. **Потеря якоря при быстром «A+» после листания.** Якорь снимался через
   240 мс после анимации, поэтому следующий ре-лейаут мог уйти по старому
   месту. Теперь якорь снимается **до** сдвига потока и передаётся в
   `onPageChange` как предпочтительный.
3. **Пустой якорь после восстановления.** Если снять якорь с экрана не
   удалось, используется последний известный: пустой якорь означал бы
   «место потеряно» и следующее открытие начиналось бы с начала книги.

### Ограничение окружения

В этой машине выставлен `HTTP_PROXY`. Chromium обходит прокси для localhost
сам, WebKit — нет: `/_next/*` уходил на прокси и возвращался как
`/localhost:3100/_next/*`, страница не гидрировалась. `playwright.config.ts`
снимает proxy-переменные перед запуском. Это особенность окружения, а не
продукта, но без неё WebKit-прогон выглядит как «CSS columns не работают».

## Как проверять

```bash
# backend
dotnet build EnglishLearningPlatform.API.Tests/EnglishLearningPlatform.API.Tests.csproj
dotnet run --project EnglishLearningPlatform.TestRunner   # 441 passed, 2 skipped

# frontend
cd frontend
npm run test:unit      # 114 passed
npm run lint
npm run build
npm run test:e2e:lab   # Chromium + WebKit + iPhone 13
```

`npm run test:e2e` дополнительно запускает `e2e/reader.spec.ts` — полный
проход по живой книге. Он включается переменными `E2E_EMAIL`, `E2E_PASSWORD`,
`E2E_BOOK_ID`; без них смоук пропускается.

## Что осталось за рамками

- `BookAnalyzerService` продолжает считать CEFR по синтетическим страницам:
  снимок читалки используется для текста, но старый анализатор не переведён
  на него. Это оптимизация, а не блокер.
- Сложные сноски и таблицы EPUB деградируют в текст — осознанный YAGNI из
  плана.
- Старые закладки маппятся приблизительно (страница × 300 слов → ближайшее
  предложение), точное совпадение после смены движка невозможно.
