# CMS-6: Медиа-хранилище и массовый импорт

Две вещи для ежедневной работы админа: файлы за интерфейсом (переезд на S3
без правки кода) и заливка сотни слов одним файлом вместо ручного ввода.

## Медиа: `IMediaStorage`

```
IMediaStorage            SaveAsync / DeleteAsync / BuildPublicUrl
   └─ LocalMediaStorage  диск под ContentRoot/uploads
   └─ (позже) S3MediaStorage  — без изменения контроллеров
```

**Что НЕ входит в контракт: имя файла.** Клиентское имя — это обход пути
(`../../appsettings.json`) и подмена чужого файла. Имя генерирует хранилище:
GUID + расширение.

**Относительные адреса, а не абсолютные.** Платформа работает с localhost,
по внешнему адресу и с телефона в той же сети. Абсолютный адрес, собранный
из base-url запроса, ломается на каждом из этих случаев — это уже ловилось
на гостевом чтении.

**Белый список расширений, а не только формат.** Регулярка `^\.\w+$` пропускает
`.exe` и `.dll` — а файл с таким именем в публичной папке статики исполняется
веб-сервером. Разрешено только медиа: webp, png, jpg, gif, svg, avif, mp3,
ogg, wav, m4a, webm, mp4.

**Защита от обхода пути** — через `GetFullPath` + сравнение с корнем **с
завершающим разделителем**. Без разделителя корень `/media` пропустил бы
соседний каталог `/media-backup`.

**Недописанный файл удаляется.** Исключение посреди записи — это «картинка
0 байт», которую никто не найдёт и не почистит.

## Импорт слов: CSV и JSON

`POST /api/admin/categories/{id}/words/import?dryRun=`

### CSV разбирается вручную, а не `Split(',')`

Перевод из настоящего словаря регулярно содержит запятую внутри кавычек и
двойную кавычку внутри поля. Наивный разбор режет такие строки и заливает
обрезанные переводы — их потом ищут руками по всему словарю.

Что обработано:

| Случай | Почему важно |
|---|---|
| `"To run, to walk"` | запятая в кавычках не делит поле |
| `"видеть (""to see"")"` | экранированная кавычка (формат Excel) |
| перенос строки внутри поля | реальный перевод часто многострочный |
| BOM `\uFEFF` от Excel | без снятия первая колонка называется `\uFEFFEnglish` |
| `english` / `ENGLISH` / `English ` | регистр и пробелы в шапке |
| файл без шапки | позиционно: слово, перевод, [транскрипция], [пример] |
| дубли внутри файла | схлопываются с предупреждением и номером строки |
| `.txt` | **отклоняется** — под ним приходит что угодно |

### Импорт не падает на плохих данных

Разбор возвращает `{Rows, Errors, Warnings}` с номерами строк. Исключение
означало бы «импорт не состоялся целиком» вместо «строка 17 неправильная».

**Одна строка не отменяет остальные:** 2 хороших слова + 1 битая → пишутся 2,
битая идёт в отчёт.

**Потолок показа ошибок — 50.** Файл на 5000 строк с шапкой не тем полем даст
5000 ошибок, и ответ на 2 МБ бесполезен.

**`dryRun=true` — ничего не пишет.** Админ видит результат до записи 500 строк.

**Дубли с базой не создаются** — сравнение без учёта регистра: `Apple` и
`apple` для ученика одно слово.

## Дефекты, найденные при работе

1. **Регулярка расширений пропускала `.exe`.** Поймал собственный тест:
   `^[a-z0-9]{1,8}$` валиден для `.exe`. Заменено на белый список медиа.
2. **`.txt` принимался как CSV** — я сам добавил его в разрешённые, а тест
   ждал отказа. Тест был прав.
3. **`Path.GetTempPath()` в тестах указывает в `C:\Temp` без прав** — тесты
   падали на создании каталога вместо проверки логики. Решение: каталог рядом
   с тестовой сборкой (`AppContext.BaseDirectory`).

## Проверено вживую

CSV с BOM, кавычками, запятой внутри поля, дублем и битой строкой:

```
dryRun:          added=2, ошибка «строка 5», предупреждение «строка 4 — дубль строки 3»
реальный импорт: added=2
повторно тот же файл: added=0, skipped=2   ← дублей нет
в базе: apple / яблоко / пример 15 символов (запятая сохранена)
строк с тестовым словом: ровно 1
```
