# CMS-4: Статьи

Постоянный контент — в отличие от новостей, которые живут две недели.
Статья пишется один раз и висит годами, поэтому у неё другой набор проблем:
кто автор, что было до правки, и почему её не видно.

## Схема (была готова с волны 1, здесь обвязка)

```
ArticleSection              Article                       ArticleRevision
├ Id                        ├ Id                          ├ Id
├ Name                      ├ Slug (uniq, active)         ├ ArticleId → Article CASCADE
├ Slug (uniq, active)       ├ Title                       ├ Revision (номер версии)
├ Description               ├ Summary                     ├ Title
├ SortOrder                 ├ BodyMarkdown   ← источник   ├ BodyMarkdown
└ DeletedAt                 ├ BodyHtml       ← кэш        ├ Status
                            ├ SectionId → ArticleSection  ├ EditedByUserId
                            └ Status (draft/published/   └ CreatedAt
                                       archived)
```

**Markdown — источник, HTML — производное.** HTML перегенерируется при
сохранении. Если завтра сменится рендерер, тексты не переписывать: канон
лежит в `BodyMarkdown`.

**Ревизия пишется ДО правки.** Иначе «админ случайно затёр текст» — это
потеря без отката, и вопрос «что было раньше» не имеет ответа.

## Решения

**Создание всегда даёт черновик.** Даже если в запросе просят `published`.
Публикация — отдельное действие с проверкой, что текст есть. Иначе «создать
и опубликовать одним POST» выпускает на сайт пустую страницу.

**Черновик и архив отдают 404 читателю, а не пустую страницу.** На статью
могли остаться ссылки из старых постов; 404 — нормальный ответ, а не сбой.

**`PublishedAt` ставится только при первой публикации.** Иначе переопубликация
старой статьи делает её «свежей» и вытесняет новые материалы наверх.

**Правка не меняет статус.** Исправить опечатку в опубликованной статье не
должно требовать повторной публикации.

**Слаги транслитерируются через общий `Services.Transliteration`.** Раньше
копия этого словаря жила в `AdminContentController`; вторая копия неизбежно
разошлась бы с первой. Заголовок без единой латинской буквы получает
`article-<hash>`, а не пустой слаг.

**`MarkdownRenderer` — singleton.** Держит собранный Markdig-pipeline и
экземпляр санитайзера; пересоздание на каждый запрос выбрасывает внутренний
кэш парсера.

**Санитизация после рендера, а не до.** Markdig по спецификации пропускает
сырой HTML из markdown как есть — «храним markdown, значит безопасно» неверно.

## Дефекты, найденные при работе

1. **Анонс из code-блока превращался в живой тег.** Внутри `<code>` текст
   `<div>x</div>` приходит экранированным (`&lt;div&gt;`). Снятие тегов, затем
   декодирование — и `<div>` снова тег, уезжающий в карточку. Нужен повторный
   проход снятия тегов после декодирования.
2. **Сидер воскрешал удалённый раздел.** Проверка `Slug == slug && DeletedAt == null`
   не находила удалённую строку и создавала вторую с тем же слагом — либо падение
   на уникальном индексе, либо два «Грамматика» в навигации. Теперь
   `IgnoreQueryFilters()`: удаление — решение человека, сидер его не отменяет.
3. **Мой тест обрезки анонса был неверен** — искал «слово…» в строке из одних
   «слово слово», что совпадает РОВНО при правильной обрезке по границе слова.
