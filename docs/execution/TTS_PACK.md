# Пак озвучки слов (TTS pack)

4500 MP3 с нейроголосом Microsoft Edge для каждого слова из
`EnglishLearningPlatform.API/Data/Seed/wordlists.json`. Клик по слову отдаётся
с диска за миллисекунды, без запроса к провайдеру, без квоты и без задержки
3–6 с. Реализует R9 (`PHASE2_CONTRACT.md`) поверх R6 (`EXECUTION_CONTRACT.md`).

| Что | Значение |
|---|---|
| Файлов | **4500** (по одному на слово, дублей в словаре нет) |
| Объём | 49.56 МиБ полезных данных (57544 блоков ≈ 57 МБ на диске) |
| Средний файл | 11.3 КБ, от 9792 до 16704 Б (моно 24 кГц, 48 кбит/с) |
| Полный прогон с нуля | **10 мин 14 с** при `--concurrency 8` (~7.3 слова/с) |
| Стоимость | 0 (Edge-TTS бесплатен, ключ не нужен) |
| Голос | `en-US-AriaNeural`, `rate=-10%` (слова учат — чуть медленнее) |

## Почему офлайн, а не на сервере

Серверный Edge-TTS — неофициальный WebSocket-протокол с меняющимся
антибот-токеном (`Sec-MS-GEC`), а на боевом VPS 1 ядро и <400 МБ свободной
памяти. Генерируем файлы один раз на машине разработчика и кладём каталог на
сервер: `uploads/tts-pack/`. Python на сервере для работы пакета **не нужен** —
это просто каталог с MP3.

## Имя файла: один контракт на троих

Бэкенд (`SpeechService.FindPackFile`), генератор (`generate.py`) и тест
(`SpeechPackCoverageTests`) считают имя одинаково:

```
sha256( "pack|" + слово.Trim() в нижнем регистре, пробелы схлопнуты ).hex + ".mp3"
```

64 hex-символа + расширение. Пример: `the` → `61afd01b71eb2afe…73a64.mp3` (68 символов).

Почему в нижнем регистре: сервер ищет слово дважды — как есть (`Alice` из
книги) и в нижнем регистре (`alice` из словаря). Оба кандидата обязаны попадать
в один файл, поэтому ключ нормализуется до генерации. Пробелы схлопываются,
потому что `NormalizeText` в сервисе делает то же самое с текстом запроса.

**Любое изменение этой формулы — и весь пак становится невидимым** для сервиса
молча: `FindPackFile` вернёт `null`, и озвучка уйдёт к провайдеру. Поэтому
формула продублирована в тесте независимо, а не берётся из продакшн-кода.

## Как прогнать

edge-tts нужен только здесь. Ставьте в изолированное окружение, чтобы не
мусорить в системный Python:

```bash
# разово: окружение и зависимость
uv venv .venv-tts --python 3.13
VIRTUAL_ENV=.venv-tts uv pip install edge-tts   # проверено на 7.3.1

# 1. Прикидка: без сети и без записи — сколько слов, сколько осталось
.venv-tts/Scripts/python tools/tts-pack/generate.py \
  --words EnglishLearningPlatform.API/Data/Seed/wordlists.json \
  --out   EnglishLearningPlatform.API/uploads/tts-pack \
  --dry-run

# 2. Полный прогон (главная команда)
.venv-tts/Scripts/python tools/tts-pack/generate.py \
  --words EnglishLearningPlatform.API/Data/Seed/wordlists.json \
  --out   EnglishLearningPlatform.API/uploads/tts-pack \
  --concurrency 8

# 3. Пилот: первые N слов по rank (быстрая проверка, что сеть жива)
… --limit 30
```

На Linux/macOS путь к интерпретатору — `.venv-tts/bin/python`.

`--dry-run` печатает `слов в списке / уже в паке / надо озвучить / огрызков`.
Он же — самый дешёвый способ узнать, дошёл ли прогон до конца: при полном паке
четыре числа должны быть `4500 / 4500 / 0 / 0`.

### Сколько времени и места

Замер полного прогона (4470 файлов, 30 уже было):

```
итог: записано 4470, уже было 30, брак 0
4500/4500 — 7.3 слов/с — 614 с
```

- ~10–15 минут на 64-ядерной машине при `--concurrency 8`; узкое место — сеть
  Microsoft, а не CPU: слово поднимает сокет, поэтому ядра простаивают.
- диск: 49.56 МиБ полезных данных (57544 блоков ≈ 57 МБ на диске). Оценка
  `--dry-run` (~10.9 МиБ) занижает факт в 4.5 раза — она считается по символам,
  а короткие слова дают слышимую паузу и тишину по краям длиннее расчётной.
  По факту 11.3 КБ на слово.
- длительность аудио суммарно **144.3 мин** (среднее слово 1.92 с) — валидно по
  MP3-кадрам у всех 4500 файлов, файлов с нулевой длительностью нет.

## Стоимость по сравнению с квотой

Пак снимает нагрузку с TTS-провайдеров: 4500 слов = **28 549 символов**
(средняя длина 6.34, максимум 18) — это 7% от `DefaultMonthlyCharLimit =
400 000` у Azure и в 100 запросов/сутки у Gemini не залезает вовсе.
Стоимость пака — 0 ₽ и 57 МБ диска.

## Докачка и обрывы сети

Прогон **идемпотентен и прерываем**:

- файл пишется в `*.mp3.tmp`, проверяется (размер + реальная длительность по
  MP3-кадрам) и только потом переименовывается — Ctrl+C/обрыв не оставит в паке
  половину файла;
- «уже есть» считается только для файла, прошедшего ту же валидацию; огрызок
  (<1 КБ, <0.3 с, >30 с, >512 КБ) перезаписывается;
- исключение сети/429 по одному слову не валит прогон: слово уходит в брак,
  остальные продолжаются.

Поэтому при обрыве просто запустите ту же команду снова — она докачает только
отсутствующее. Отбракованные слова печатаются строкой `БРАК <слово>: <причина>`
в stderr и попадают в итоговую строку `брак N`. Если `брак > 0`, прогон
завершился с кодом 1 — повторите; при повторе не пройдёт только действительно
проблемное слово.

Словарь меняется (добавили слово) — ничего не перегенерируется, кроме нового
файла: ключ зависит только от текста слова.

## Как проверить полноту

Два независимых способа, оба реальные:

```bash
# 1. количество файлов и объём
find EnglishLearningPlatform.API/uploads/tts-pack -type f -name '*.mp3' | wc -l   # 4500
du -sh EnglishLearningPlatform.API/uploads/tts-pack                                 # ~57M

# 2. тест «пак полный» — считает имя по формуле сервиса для всех 4500 слов
dotnet run --project EnglishLearningPlatform.TestRunner --no-build \
  2>&1 | grep -E "SpeechPackCoverage|Итог"
```

`SpeechPackCoverageTests` (2 факта):

- `Все_слова_словаря_есть_в_паке` — 4500 слов из сида, для каждого строится имя
  и проверяется существование + размер >1 КБ. В сообщении при падении — сколько
  покрыто и первые 10 отсутствующих/битых слов. Зелёный только при 4500/4500.
- `В_паке_нет_файлов_вне_словаря` — обратная сторона: лишние файлы (след старого
  голоса или удалённого слова) и брошенные `*.tmp`.

Каталог пака тест находит от каталога сборки (`EnglishLearningPlatform.slnx`
выше), а не от cwd — запускать раннер можно откуда угодно, но **из этого
рабочего дерева**: тест читает настоящий `uploads/tts-pack`, а не временную папку.
На сервере артефакт сам по себе лежит рядом с exe, копирования не требуется.

### Частая ложная тревога

`dotnet build` падает с `MSB3027: … EnglishLearningPlatform.API.exe … блокирует
этот файл`. Это запущенный стенд, а не сломанный код. Останавливать API нельзя
(стенд общий), поэтому собирайте раннер в обход его `bin` — и направьте тест на
корень дерева переменной `ELP_REPO_ROOT` (без неё тест ищет
`EnglishLearningPlatform.slnx` вверх от своей сборки):

```bash
dotnet build EnglishLearningPlatform.TestRunner/EnglishLearningPlatform.TestRunner.csproj \
  -c Debug -p:UseAppHost=false \
  -p:BaseOutputPath=C:/abs/path/to/.tmp/vp-bin/
dotnet .tmp/vp-bin/Debug/net10.0/EnglishLearningPlatform.TestRunner.dll \
  --filter SpeechPackCoverage     # при oracle-сборке вне дерева: ELP_REPO_ROOT=$PWD
```

Проверено: при `-p:BaseOutputPath=./относительный` msbuild склеивает путь в
мусор (`UsersNikitaDesktop…`) — путь к каталогу обязан быть абсолютным.
`-p:UseAppHost=false` убирает ещё и второй lock (на копировании `apphost.exe`).

Если кроме lock-ошибки появились `CS…` — это чужая незакоммиченная правка в
`EnglishLearningPlatform.API.Tests/`, и ваш тест тут ни при чём: соберите только
этот файл (скопировать `SpeechPackCoverageTests.cs` с `.csproj` в scratch и дать
`<Reference>` на `obj/Debug/net10.0/EnglishLearningPlatform.API.dll` вместо
`ProjectReference`) — так проверялся пак, пока соседний агент правил
`WordExampleSeederTests.cs`.

## Смена голоса: старые файлы не подойдут

Имя файла — хеш **текста**, а не голоса. Поэтому смена `--voice`/`--rate`:

- **не** перегенерирует ничего: генератор видит файл, он валиден, слово
  пропускается — в паке останутся два голоса вперемешку (старые слова прежним,
  новые новым);
- `SpeechService` продолжит находить и отдавать старый файл — молча, без ошибки.

Порядок при смене голоса:

```bash
# 1. старый пак убрать (он больше не нужен и не должен попасть на сервер)
rm -f EnglishLearningPlatform.API/uploads/tts-pack/*.mp3
# 2. прогнать заново с новым голосом — полный прогон, ~10 мин
… --voice en-US-JennyNeural --rate=-10%
# 3. проверить полноту тестом (см. выше): 4500/4500
```

Проверка «а каким голосом этот пак?» — по обложке нет: метаданных у MP3 нет.
Храните голос/rate в этом файле (таблица выше) и меняйте строку своевременно.
Если когда-нибудь понадобится держать два голоса одновременно — добавляйте
голос в ключ (`pack|<voice>|<слово>`) и в `SpeechService.GetPackKey`
одновременно; до этого такой правки нет.
