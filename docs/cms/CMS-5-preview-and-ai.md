# CMS-5: Предпросмотр markdown и AI-ассистент

Две вещи, без которых админка — это форма с textarea: увидеть текст до
публикации и не писать с нуля.

## Предпросмотр markdown

`src/lib/markdown-preview.ts` + `MarkdownField.tsx` — переключатель
«Редактор / Просмотр».

**Порядок операций критичен: экранирование ВСЕГО входа, потом разметка.**
Не наоборот. Если сначала накладывать разметку, а потом чистить — между этими
шагами ввод уже стал HTML, и любой пропущенный случай становится исполняемым.

Проверено на 7 векторах, реально опасных — 0:

| Вход | Результат |
|---|---|
| `<script>alert(1)</script>` | текст `&lt;script&gt;…` |
| `<img src=x onerror=…>` | текст |
| `<svg onload=…>` | текст |
| `<iframe src=javascript:…>` | текст |
| `[x](javascript:alert(1))` | не становится ссылкой |
| `[x](jav&#x61;script:…)` | не становится ссылкой |
| `[a](https://ok" onmouseover="…)` | кавычка → `&quot;`, атрибут не разрывается |

`safeHref` пускает только `http(s)`, `mailto` и относительные пути.

Один нюанс методики: первый прогон проверки дал «7 опасных из 10» — это были
ложные срабатывания моего детектора, который искал подстроку `onerror` в
**экранированном тексте**. Текст `&lt;img onerror=…&gt;` безопасен. Строгий
детектор ищет живые теги с обработчиками и href с декодированной схемой.

## AI-ассистент

`POST /api/admin/assistant/article` — черновик по теме, уровню и аудитории.
`POST /api/admin/assistant/word-examples` — примеры к слову.
`GET /api/admin/assistant/status` — остаток лимита для подписи под кнопкой.

### Отдельный бюджет — главное решение

`Ai:AdminDailyRequestLimit` (по умолчанию 100) не пересекается с
`DailyUserRequestLimit` (300). Тип запроса пишется в `AiUsageLogs` с префиксом
`admin-`, и админская квота считает только их.

Почему не общая квота:
- **В одну сторону:** редактор пишет статью — это десятки вызовов подряд. На
  общих 300 он упрётся в отказ посреди текста.
- **В другую:** админ, пишущий весь день, оставит учеников без переводов.

Тесты держат обе стороны, включая обратную: 100 админских вызовов не тратят
квоту ученика.

**Ноль в конфиге — это «выключено», а не «безлимит».** Опечатка не должна
открывать неограниченный расход на чужой счёт.

**Кэш не используется** в отличие от пользовательской генерации: админ жмёт
«сгенерируй» второй раз, потому что первый вариант не понравился. Кэш вернул
бы ему тот же абзац.

### Коды отказа

| Ситуация | Код | Почему так |
|---|---|---|
| Пустая тема | 400 | до провайдера, не тратя бюджет |
| Лимит исчерпан | 429 | ожидаемое «на сегодня всё», не 500 |
| Ассистент выключен в конфиге | 503 | «попробуйте завтра» было бы враньём |
| ИИ недоступен | 503 | честно, с текстом для человека |

## Дефекты, найденные при приёмке

1. **`AiEndpointGateTests` поймал новый контроллер.** Платный AI-вызов был
   доступен аккаунту без подтверждения почты — существующий тест безопасности
   `SECURITY_GATE R-06` не пропустил. Добавлен `[RequireConfirmedEmail]`.
2. **`next build` снёс dev-бандлы.** После `npx next build` все `/_next/static/*`
   отдавали 404, страница входа гидратировалась без JS и форма уходила
   **GET-запросом с паролем в адресной строке**. Это не дефект кода — но
   важное предупреждение: после сборки dev-сервер нужно поднимать заново,
   иначе получаешь мёртвый интерфейс и утёкший пароль в истории браузера.

## Блокер: AI не проверен вживую

```
Gemini:       ApiKey = "SET_IN_ENV" → таймаут 3 попытки
Pollinations: HTTP 402
Локальный:    level_map только для слов
```

Код корректно отдаёт 503 при недоступном ИИ (это и проверил), но качество
генерации без ключа подтвердить нельзя.

**Чтобы проверить:**
```bash
GEMINI__APIKEY=<ключ> bash scripts/dev-cms.sh
```
Ключ бесплатный: https://aistudio.google.com/apikey
